Симулятор планировщиков 5G/6G

Симулятор разработан для курсовой работы по дисциплине «Проектирование систем управления». Радиоресурсы одной соты делят три класса трафика: URLLC, eMBB и mMTC. Классические планировщики сравниваются с предиктивным (MPC) на одних и тех же траекториях канала и нагрузки.

Стоимость SLA: приоритет классов
Стоимость SLA = сумма «вес × доля нарушений дедлайна класса, %». Это способ оценки, а не параметр алгоритма: моделирование не сбрасывается. Чем меньше, тем лучше.
Параметры MPC

Горизонт: 10 слотов (5G), 8 слотов (6G). Изменение параметров сбрасывает моделирование.

Что показывают результаты

  • MPC даёт нарушения дедлайна URLLC почти как строгие приоритеты (2,7–3,5% против 0,7–1,9%) и в 2,5–4,5 раза меньше, чем PF.
  • В отличие от строгих приоритетов, MPC не оставляет mMTC без ресурсов (у PRIO 80–89% нарушений) и держит индекс Джейна около 0,97–0,99.
  • Цена: по eMBB MPC хуже PF и PRIO. Квадратичный критерий выравнивает задержки, и пакеты eMBB ждут почти до дедлайна.
  • Расчёт одного слота в Python занимает несколько миллисекунд, это дольше длительности слота. Для реального времени нужна другая реализация.

Как устроено моделирование

  • Один слот: приход пакетов, оценка канала, выбор числа RB для каждого из 20 пользователей, передача, учёт задержек.
  • Канал: релеевские замирания, процесс AR(1) с коэффициентом a = J0(2π·fd·Ts), средний SNR пользователя из N(10; 4) дБ, скорость 3, 30 или 60 км/ч.
  • Трафик: URLLC и mMTC приходят по Пуассону, eMBB идёт вспышками (ON/OFF, пик вдвое выше среднего).
  • Нарушение дедлайна: пакет доставлен позже бюджета задержки своего класса. Недоставленные пакеты учитываются по возрасту.
бит на RB = 168·(1−0,14)·min(η_max; 0,6·log2(1+SINR))
E[g(k)] = 1 − a^(2k) + a^(2k)·g0      прогноз канала
J = ½ Σ φ_i · Q_i,k²  +  κ · недобор до дедлайна
φ_i = W_c·(1 + β·min(возраст/D_c; 3)) / масштаб_i²

Допущения и ограничения

  • Одна сота, широкополосный SINR, CQI текущего слота без ошибок, без HARQ.
  • Предиктор знает структуру AR(1)-канала, поэтому оценка оптимистична.
  • MPC в браузере решает тот же критерий ускоренным проекционным градиентом. В Python использован OSQP. На одинаковых траекториях результаты близки, но числа для работы нужно брать из Python.
